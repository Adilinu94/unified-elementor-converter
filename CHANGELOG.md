- Derived the consolidated, versioned wizard-contract schema (O-12): `@elconv/core/contracts/wizard-contract.contract.ts` defines `WizardContractSchema` (Zod) as the single source of truth — the `WizardContract` types are inferred from it (`z.infer`), `validateWizardContract()` soft-validates parsed artifacts with uniform `path: message` issues (reusing `formatZodIssues` from config), and `wizardContractJsonSchemaDocument()` deterministically derives the versioned JSON-Schema document (draft 2020-12, `$id: elconv/wizard-contract/v1`). Contracts now self-describe via `$schema` and `writeWizardContract` refuses to persist an invalid artifact. The committed `schemas/wizard-contract.schema.json` is generated by `scripts/export-wizard-contract-schema.ts` and pinned by a drift-guard test; 16 validation tests cover the machine gate (`schemaVersion`), `$schema` presence, exit-code/status/strictness enums, the `optionsAppliedToBuild` parity record and the schema metadata.
- Added the pre-O-12 wizard-contract migration (O-12 follow-up): `migrateWizardContract()` in `@elconv/core` detects artifacts without `$schema` (written before O-12), stamps the current schema id, fills missing option fields with the wizard defaults (`WIZARD_CONTRACT_DEFAULTS`, pinned by a drift guard against `createWizardState`), derives a missing `optionsAppliedToBuild` parity record, completes the phase list from the canonical order (status `ok` for completed runs / `pending` while running / `skipped` otherwise) and validates the migrated value against the versioned schema — foreign schema ids and still-invalid values are rejected honestly, never coerced. `readWizardContract()` in the CLI reads any `wizard-contract.json` (old or new) with that single validator and reports file/JSON errors as structured results. Covered by 19 new migration tests.
- Prepared the remote pipeline-state mock contract (O-04/O-12 follow-up): `packages/cli/src/remote-state.ts` defines the `WizardRemoteStateAdapter` interface (`save`/`load`/`resume` plus an explicit `status` verification gate) with a single factory `createRemoteStateAdapter()`. The honest gate is structural: unless the adapter is created `verified` with an injected pipeline-state executor, every operation reports `unavailable` and the MCP client is never invoked — no code path can write remote state before the server-side `novamira-adrianv2/pipeline-state` schema is verified against a real test target. Persisted payloads are wrapped in `WizardRemoteStateEnvelope` in `@elconv/core`, which self-describes via `$schema: elconv/wizard-contract/v1` (referencing the committed `schemas/wizard-contract.schema.json`) and shares its `schemaVersion: 1` machine gate; `validateWizardRemoteStateEnvelope()` validates reference/gate/pipelineId/savedAt/state. `createMockRemoteStateAdapter()` implements the same contract as an offline in-memory harness, and error paths (`unavailable`, `notFound`, `invalid-envelope` — never silent coercion, server-failure propagation) are covered by 21 new offline tests including a drift guard pinning the envelope `$schema` to the committed schema `$id`.
- Prepared the ability-schema codegen (O-12 follow-up): `packages/mcp/src/ability-schema.ts` derives a versioned JSON-Schema document deterministically from the ability registry (`KNOWN_ABILITIES`/`ALIAS_MAP`/`UNAVAILABLE_ABILITIES` — the frozen live-server snapshot): `abilityJsonSchemaDocument()` produces the `schemas/novamira-abilities.schema.json` artifact (`$id: elconv/novamira-abilities/v1`, `schemaVersion: 1` machine gate, a `knownAbilities` enum of all 263 names, the alias map, documented unavailable gaps and per-namespace counts), `abilityNamespace()`/`abilityNamespaceCounts()` group namespaces deterministically, and `buildAbilityRegistrySnapshot()` builds the self-describing payload the schema describes. `scripts/export-ability-schema.ts` regenerates the artifact (analogue to the wizard-contract schema). 12 new tests pin the schema metadata, exact enum coverage (263 names, only known ones), the root machine gate, determinism, namespace counts (sum = 263, `mcp-adapter` = 1), the snapshot payload against the registry, plus two drift guards: the committed schema file must equal the generated document, and `docs/NOVAMIRA-LIVE-ABILITIES-2026-07-30.txt` must contain exactly the `KNOWN_ABILITIES` set.
- Wired `readWizardContract` into the wizard resume path (O-12 productive wiring): `reportWizardContractOnResume()` in `cmd-wizard.ts` reads the `wizard-contract.json` next to the state file on `--resume`, soft-migrates pre-O-12 artifacts (missing `$schema`) and visibly confirms the outcome (`✓ valid` / `✓ migrated from pre-O-12 (N change(s) applied)` / `⚠ invalid` with per-issue lines). The check is best-effort: a missing contract stays silent and an invalid contract never blocks the resume — the state file remains the source of truth and the exit code is unchanged. Covered by 4 new CLI tests (valid, migrated, invalid-without-block, silent-when-absent).
- Bridged the mock remote adapter onto the wizard's remote-state port (O-04/O-12): `bridgeRemoteStateAdapter()` in `remote-state.ts` maps the result-shaped `WizardRemoteStateAdapter` onto the throwing/`null` port contract — `notFound` becomes `null` (a "start fresh" condition, never an error), and any other failure (including an invalid envelope) becomes a thrown error, never a silent coercion. `WizardDependencies.remoteState` now accepts `WizardRemoteStateAdapter | WizardRemoteStatePort`; `cmdWizard` normalizes exactly once via `toRemoteStatePort()` and threads the port through the resume load, `persistWizardState` and the state machine, while `persistContract` honestly reports an injected adapter that says `verified: false` (`remote-state adapter injected but not verified: <reason>`). Resume via `--remote-state-key` is now testable offline end-to-end (save/load/resume + envelope validation) without any productive MCP activation. Covered by 3 new wizard tests (done-run resumed purely from the remote key; a two-run save→resume roundtrip through the same mock instance including the envelope `$schema`; an invalid remote envelope surfacing as exit 2) and 2 new bridge tests in `remote-state.test.ts` (roundtrip, notFound→null, unavailable→throw).
- Extended `elconv doctor` with a standalone wizard-contract check (O-12 follow-up): `--wizard-contract <state-file>` reads the `wizard-contract.json` next to a wizard state file via the same `readWizardContract` path as the resume wiring — soft-migrating pre-O-12 artifacts and validating against the versioned schema — without resuming the wizard.
